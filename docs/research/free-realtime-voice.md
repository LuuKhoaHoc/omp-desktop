# Free realtime voice for OMP Desktop

**Research date:** 2026-11-11  
**Scope:** Streaming speech input and output, interruption/turn detection, tool calls, Vietnamese, costs, wire protocol, privacy, and practical fit on a GTX 1650 4 GB / 12-thread PC. Provider free-tier quotas change often; the linked vendor page is authoritative, and a missing numeric quota is marked *not published or not confirmed*, not guessed.

## Short answer

No reviewed hosted option combines a dependable free quota, Vietnamese speech in/out, direct OpenAI Realtime wire compatibility, and tool execution. Google Gemini Live is the best free hosted experiment: it has audio-to-audio streaming, VAD/interruption and function calls, but uses Google's WebSocket protocol and free-tier data can be used to improve its products. For a private, free local server, Hugging Face `speech-to-speech` exposes OpenAI Realtime-compatible WebSocket and WebRTC transports with tool events, but its out-of-box language support depends on separately selected STT/TTS/LLM models. A 4 GB GTX 1650 is a constraint, not a proven turnkey configuration. Speaches is another compatible server, but explicitly lacks cancellation/truncation today and relies on a separate LLM provider for useful dialogue.

“Realtime-compatible” means the client event protocol, not an implementation of OpenAI's proprietary speech model. None of the local options is OpenAI Realtime itself. The Realtime client can send function calls, but the application must execute them and return results.

### Hosted protocol conclusion

None of the hosted non-OpenAI rows can be assumed to accept an OpenAI Realtime WebRTC SDP exchange plus `oai-events` data channel unchanged. OpenAI Realtime itself does. Gemini, Hume, Deepgram, ElevenLabs, Ultravox and Groq/Cloudflare component APIs need an adapter or a framework integration. Azure may accept OpenAI-style Realtime events for a compatible deployment/API version, but endpoint, auth and API-version differences remain. LiveKit is a WebRTC transport/framework, not a model-protocol substitute.

## Ranked shortlist for this user

### 1. Gemini Live through AI Studio: simplest free hosted trial

**Why:** Native low-latency voice conversation, turn detection and function calling; free eligible tier; no local GPU burden. Downsides: Google wire protocol means an adapter is required, free-tier data may be used to improve products, quotas are model-specific, and Vietnamese output quality needs a real test.

**Steps:**
1. Sign in to [Google AI Studio](https://aistudio.google.com/) and create an API key.
2. Confirm a currently free Live model and its per-model request/token limits at [pricing](https://ai.google.dev/gemini-api/docs/pricing) and [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits).
3. Connect over Gemini Live WebSocket (`BidiGenerateContent`) using the official SDK; configure audio output and VAD.
4. Register OMP actions as Gemini function declarations; dispatch returned calls into the existing agent RPC/tools layer and return function responses.
5. Test Vietnamese audio input/output, interruption, noisy-room VAD, and tool argument fidelity before adopting. Keep free-tier sensitive code/audio out if Google's stated data-use terms are unacceptable.

### 2. Hugging Face `speech-to-speech`: best protocol fit for a local adapter

**Why:** OpenAI Realtime-compatible WebSocket and WebRTC, with function-call event flow and interruption support. Software is free and can be self-hosted. Downsides: a compatible protocol is not a model; Vietnamese needs a chosen multilingual STT and Vietnamese TTS, and the 4 GB GPU has no documented turnkey low-latency recipe.

**Steps:**
1. Install from the [project repository](https://github.com/huggingface/speech-to-speech) using its documented `uv` workflow; start with the local demo and loopback binding.
2. Query `/v1/realtime/capabilities` to inspect configured STT/TTS language metadata; choose handlers that explicitly declare Vietnamese.
3. Test local GPU memory and end-to-end first-audio latency with the GTX 1650; if inference misses realtime targets, use a smaller quantized model or a remote LLM/TTS (then it is no longer fully local/free).
4. Point OMP's Realtime client at the server endpoint; use the stock WebSocket or WebRTC transport. Map function calls to OMP tools and return `function_call_output`.
5. Review each model's own license and data path. Local inference can keep audio on-device; cloud-backed handlers transmit it to that provider.

### 3. Speaches + separate LLM: straightforward local OpenAI-style WebSocket, with caveats

**Why:** Simple OpenAI-compatible Realtime WebSocket and local Whisper/Kokoro options. Downsides: interrupt cancellation/truncation is currently missing; default Kokoro voices are English; a separate LLM is required for reasoning/tool calls. This is not an all-local Vietnamese voice agent out of the box.

**Steps:**
1. Run Speaches using the [official installation guide](https://speaches.ai/installation/) with CUDA enabled if available.
2. Load a multilingual Whisper checkpoint for Vietnamese input. Select a Vietnamese-capable TTS model separately; do not assume default Kokoro supports Vietnamese.
3. Configure the Realtime conversation endpoint with a separately hosted or paid LLM that can execute OMP tool calls.
4. Point an OpenAI Realtime WebSocket client at `/v1/realtime`; adapt/disable client-side interruption behaviors unsupported by Speaches.
5. Benchmark concurrent STT/TTS memory and latency. A local install costs no API fee, but models and hardware still have operational cost.

**Recommendation:** Start with Gemini Live for a practical free hosted prototype if free-tier data handling is acceptable. Use HF `speech-to-speech` if the requirement is OpenAI Realtime wire compatibility and local control. Do not promise free, fully local Vietnamese speech on the GTX 1650 until a selected multilingual STT/TTS/LLM combination passes a latency and VRAM test. If unchanged protocol plus reliable Vietnamese output is the hard requirement, reviewed sources do not establish a free, turnkey answer.
